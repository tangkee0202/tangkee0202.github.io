第一次接触巡检机器人时，经常会连续遇到 5G LAN、边缘计算、SLAM、IMU、Odom 和 Nav2 等术语。单独看，它们似乎属于不同领域；放进一个机器人系统里，它们其实构成了一条很清晰的技术链：网络负责连接，边缘计算负责就近处理，传感器负责感知，SLAM 负责定位与建图，Nav2 负责规划并执行运动。

本文以桥梁、隧道和施工现场的巡检机器人为例，把这些概念串起来说明。

## 一张图看懂完整系统

```text
摄像头 / 激光雷达 / IMU / 轮速编码器
                    │
                    ▼
        状态估计与传感器融合
          IMU + Odom + LiDAR
                    │
                    ▼
          SLAM：定位 + 建图
                    │
           地图与机器人位姿
                    ▼
       Nav2：规划、避障、控制
                    │
                    ▼
          机器人执行巡检任务

现场数据 ── 5G LAN ── 边缘服务器
                         │
              缺陷识别、三维重建、告警
```

其中，SLAM 和 Nav2 解决的是“机器人怎样知道自己在哪、怎样到达目标”的问题；5G LAN 和边缘计算解决的是“设备怎样可靠连接、数据在哪里处理”的问题。

## 1. 5G LAN：用 5G 组成企业局域网

5G LAN 通常指 **5G Local Area Network，即 5G 局域网**。它利用 5G 网络，把同一工厂、园区或施工区域中的机器人、摄像头、传感器和服务器组成逻辑上的局域网。

它与家用路由器里的“5G Wi-Fi”不是同一个概念：

- 5G Wi-Fi 通常指工作在 5 GHz 频段的无线局域网；
- 5G LAN 指基于第五代移动通信网络提供的局域网连接能力。

在巡检场景中，5G LAN 可以让多台机器人与现场服务器保持连接，并按任务或权限划分设备组。机器人采集的视频、点云和状态信息可以通过网络发送给边缘服务器，控制中心也可以下发巡检路线和任务。

但需要注意，5G LAN 只是通信基础设施，本身并不负责定位、建图或路径规划。

## 2. 边缘计算：把计算能力放到现场

边缘计算是指把计算任务放在更靠近数据产生位置的设备上处理，而不是把所有原始数据都传到远处的云服务器。

例如，桥梁巡检机器人持续采集高清视频和激光点云。如果把全部数据实时上传云端，不仅消耗大量带宽，还可能因网络波动产生延迟。采用边缘计算后，可以在桥梁现场、施工园区或基站附近部署边缘服务器，直接完成：

- 裂缝与锈蚀识别；
- 点云配准和三维重建；
- 多机器人任务调度；
- 异常告警和数据筛选；
- 地图更新与局部路径计算。

边缘计算的主要价值是低延迟、节省带宽、提高数据隐私性，并让部分功能在外网不稳定时仍能运行。

可以用一句话概括：**云计算是把数据送去计算，边缘计算是把计算能力搬到数据旁边。**

## 3. SLAM：一边判断位置，一边建立地图

SLAM 的全称是 **Simultaneous Localization and Mapping**，中文通常译为“同步定位与地图构建”或“即时定位与地图构建”。

机器人进入未知环境时，会同时面对两个互相依赖的问题：

1. 要建立准确地图，需要先知道机器人采集每帧数据时的位置；
2. 要判断机器人位置，又需要一张地图作为参照。

SLAM 的任务就是同时估计这两个未知量。机器人不断采集摄像头图像、激光雷达点云、IMU 和轮速数据，比较当前观测与历史观测，再逐步修正自身轨迹和环境地图。

常见方案包括：

- **视觉 SLAM**：主要使用单目、双目或 RGB-D 相机；
- **激光 SLAM**：主要使用二维或三维激光雷达；
- **视觉惯性 SLAM**：融合摄像头与 IMU；
- **激光惯性 SLAM**：融合激光雷达与 IMU；
- **多传感器融合 SLAM**：进一步结合轮速计、GNSS 等信息。

桥梁箱梁、隧道和地下空间经常存在光照差、结构重复、卫星信号缺失等问题。因此实际系统通常不会只依靠一种传感器，而会通过多传感器融合提高稳定性。

## 4. IMU：感知机器人怎样加速和旋转

IMU 的全称是 **Inertial Measurement Unit**，中文叫“惯性测量单元”。它通常包含：

- 加速度计：测量三个方向的加速度，也能感知重力方向；
- 陀螺仪：测量绕三个轴旋转的角速度；
- 部分设备还包含磁力计：辅助判断朝向。

IMU 更新频率高，能够快速感知机器人转弯、倾斜、颠簸和短时运动变化。在路面不平、机器人突然转向或激光雷达暂时缺少有效特征时，IMU 可以提供连续的运动信息。

但 IMU 不能长时间独立给出可靠位置。位置通常需要对加速度进行两次积分，即使测量中只有很小的偏差，经过积分后也会不断累积，最终形成明显漂移。

因此，IMU 更像机器人的“运动感觉器官”，而不是单独使用的精确定位系统。

## 5. Odom：累计机器人从起点走到了哪里

Odom 是 **Odometry** 的简称，中文通常叫“里程计”或“里程估计”。它描述机器人相对于某个起点的位置、朝向和速度。

Odom 不一定是一件具体硬件，更常见的是由传感器数据计算出的结果。根据数据来源，它可以分为：

- **轮式 Odom**：根据左右轮编码器的转数估计移动距离和转角；
- **视觉 Odom**：通过匹配连续相机图像估计相对运动；
- **激光 Odom**：通过匹配前后两帧或多帧激光点云估计相对运动。

因此，激光雷达确实可以直接参与生成 Odom。“Odom”描述的是相对运动估计结果，而不是只代表轮速编码器。

IMU 与 Odom 的核心区别如下：

| 对比项   | IMU                              | Odom                                     |
| -------- | -------------------------------- | ---------------------------------------- |
| 本质     | 一组惯性传感器及其测量数据       | 对机器人运动轨迹的估计结果               |
| 主要输出 | 加速度、角速度，有时包含姿态     | 位置、朝向、线速度、角速度               |
| 常见来源 | 加速度计、陀螺仪、磁力计         | 轮速编码器、相机、激光雷达或融合算法     |
| 优势     | 更新快，对短时旋转和运动变化敏感 | 能直接表达相对位姿和移动距离             |
| 典型误差 | 积分误差持续累积                 | 车轮打滑、地面颠簸或环境特征不足导致漂移 |

例如，机器人向前行驶并左转时：

- IMU 告诉系统“机器人正在以多大角速度左转、当前加速度是多少”；
- Odom 告诉系统“机器人相对起点前进了约 3 米、方向改变了约 30°”。

不同来源的里程估计都可能漂移。机器人可以通过扩展卡尔曼滤波或联合优化，融合 IMU、轮式 Odom、视觉 Odom、激光 Odom 和 GNSS 等信息，得到更平稳的状态估计；SLAM 再利用更大范围的环境约束进一步修正长期误差。

这里所说的“与激光雷达融合”，需要根据系统的数据链来理解：

```text
轮速编码器 → 轮式 Odom ─┐
IMU        → 惯性信息   ──┼→ 融合后的运动估计
激光雷达   → 点云匹配   ──┘
```

例如，车轮打滑时，轮式 Odom 可能认为机器人前进了 1 米，激光点云匹配却显示机器人实际只前进了约 0.7 米。系统可以利用激光结果修正轮式 Odom 的误差。

但如果当前 Odom 本身就是由激光点云匹配计算出来的激光 Odom，那么激光雷达已经参与了它的生成，不应再把同一份信息当成独立观测重复融合。此时仍然可以把激光 Odom 与轮速、IMU 或 GNSS 等其他来源融合。

## 6. SLAM 与 Odom 是什么关系

Odom 通常提供连续、平滑的短期运动估计，但误差会随着行驶距离增加而累积。SLAM 会利用环境中的墙面、立柱、梁体、回环等约束，对累计误差进行修正。

在 ROS 语境中，`odom` 还可能有三种相关但不同的含义：里程估计数据、发布这些数据的 `/odom` 话题，以及名为 `odom` 的坐标系。交流时先确认具体指哪一个，可以避免很多误解。

在 ROS 机器人系统中，可以把三个常见坐标关系理解为：

```text
map ── SLAM 提供全局修正 ──> odom ── 里程计提供连续运动 ──> base_link
```

- `map`：地图坐标系，适合表达机器人的全局位置；
- `odom`：里程计坐标系，短时间内连续平滑，但会慢慢漂移；
- `base_link`：机器人机体坐标系。

SLAM 并不是简单替代 Odom。较好的系统通常保留 Odom 的连续性，同时由 SLAM 修正它相对于地图的长期偏差。

## 7. Nav2：有了地图以后，决定怎样走

Nav2 是 ROS 2 中常用的移动机器人导航框架。SLAM 负责回答“我在哪里、周围环境是什么样”，Nav2 则主要回答“怎样安全到达目标”。

Nav2 的典型工作包括：

- 接收地图和机器人位姿；
- 根据目标点计算全局路径；
- 根据附近障碍物持续调整局部运动；
- 向底盘发送速度指令；
- 通过行为树组织导航、恢复和任务逻辑。

所以，SLAM 和 Nav2 不是竞争关系，而是上下游关系：

```text
传感器 → Odom / 状态估计 → SLAM → 地图与位姿 → Nav2 → 底盘运动
```

机器人也可以先完成建图并保存地图，之后只做定位和导航，不必每次巡检都重新建图。

## 8. 放进桥梁巡检任务中会怎样运行

假设一台履带式机器人要进入钢箱梁内部巡检，它的完整工作流程可能是：

1. 激光雷达扫描梁体内部，相机拍摄裂缝、锈蚀和连接部位；
2. IMU 感知机器人的转动和颠簸，轮速编码器生成基础 Odom；
3. 融合算法结合 IMU 与 Odom，输出连续的运动估计；
4. 激光 SLAM 根据点云和运动估计建立地图，并修正累计漂移；
5. Nav2 根据巡检目标点规划路径，绕开临时障碍；
6. 图像和点云通过 5G LAN 传输至现场边缘服务器；
7. 边缘服务器完成缺陷识别、三维定位和告警，只把结果及必要数据上传云端；
8. 缺陷位置被投影到地图或 BIM 模型中，供后续复核和养护使用。

这条链路同样适用于隧道、电缆沟、施工现场和地下空间，只是机器人的底盘形式、传感器配置和算法参数会有所不同。

## 9. 桥梁与土木方向的延伸阅读

如果准备继续了解“桥梁巡检机器人 + SLAM + ROS 2/Nav2”，可以从下面几类文献入手。以下论文均可通过 DOI 或出版社页面进一步核验。

### 桥梁巡检与 SLAM

1. Feng 等在桥梁检测中融合多种传感器、SLAM 与图像超分辨率，用于裂缝评估和定位：[Crack assessment using multi-sensor fusion SLAM and image super-resolution for bridge inspection](https://doi.org/10.1016/j.autcon.2023.105047)。
2. Peel 等研究桥梁支座狭小空间内的移动机器人定位，对 AMCL 与 Hector-SLAM 进行了比较：[Localisation of a mobile robot for bridge bearing inspection](https://doi.org/10.1016/j.autcon.2018.07.003)。
3. Lim、La 和 Sheng 将裂缝检测、机器人定位和全局裂缝地图结合起来：[A Robotic Crack Inspection and Mapping System for Bridge Deck Maintenance](https://doi.org/10.1109/TASE.2013.2294687)。
4. Ge 和 Sadhu 将 LiDAR、单目视觉、SLAM 与结构损伤识别集成到地面机器人系统中，并进行了全尺寸桥梁实验：[Deep learning-enhanced smart ground robotic system for automated structural damage inspection and mapping](https://doi.org/10.1016/j.autcon.2024.105951)。

### 施工、隧道与相近环境

1. Yarovoi 和 Cho 的综述集中讨论施工机器人中的 SLAM，并比较多种 LiDAR SLAM 方法：[Review of SLAM for construction robotics applications](https://doi.org/10.1016/j.autcon.2024.105344)。
2. Yang 和 Cai 针对人员、设备频繁移动的施工现场，将动态目标分割与场景语义引入视觉 SLAM：[Enhanced visual SLAM for construction robots](https://doi.org/10.1016/j.aei.2023.102313)。
3. Moura、Rizzo 和 Serrano 将 BIM 信息加入移动机器人的定位与建图过程：[BIM-based Localization and Mapping for Mobile Robots in Construction](https://doi.org/10.1109/ICARSC52212.2021.9429779)。

### ROS 2 与 Nav2 基础

1. Macenski 等的 [The Marathon 2: A Navigation System](https://doi.org/10.1109/IROS45743.2020.9341207) 是了解 Nav2 系统结构的重要论文。
2. [SLAM Toolbox: SLAM for the dynamic world](https://doi.org/10.21105/joss.02783) 介绍了 ROS 2 中常用的二维激光 SLAM 工具。
3. [Regulated Pure Pursuit for Robot Path Tracking](https://doi.org/10.1007/s10514-023-10097-6) 介绍 Nav2 中常用的一类路径跟踪控制方法，对狭窄环境导航具有参考价值。

需要区分的是：桥梁和土木场景中的 SLAM 论文较多，但明确采用 ROS 2 Nav2 的论文相对较少。阅读文献时，应分别确认论文解决的是定位建图、路径规划、运动控制，还是完整的自主巡检系统，不能仅凭标题中的“自主导航”就认定它使用了 Nav2。

## 总结

这些概念可以压缩成六句话：

- **5G LAN**：让现场设备通过 5G 组成局域网络；
- **边缘计算**：让数据尽量在靠近现场的位置完成处理；
- **IMU**：测量加速度和旋转，是机器人的运动感觉器官；
- **Odom**：累计机器人相对起点的位置、方向和速度；
- **SLAM**：在未知环境中同时定位并建立地图；
- **Nav2**：利用地图和位姿完成规划、避障与运动控制。

真正可靠的巡检机器人并不依赖某一个单独模块，而是依靠网络、计算、感知、定位、建图和导航之间的协同。理解这条完整链路以后，再学习具体算法或搭建 ROS 2 系统，就不容易被大量缩写弄乱方向。
